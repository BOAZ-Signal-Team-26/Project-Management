**제안:**

**제안:**

```
3. 팀 용량 추정 규칙 수립 (담당: 대현, 기한: 3주)
```

## 8. Ticket 제목 유형 태그 (미합의)

**상태:** Notion Issue 선택지와 별도로, 제목의 태그 규칙은 팀이 정한 기록 없음

### 8-1. 제목 선택지

**제안:** Notion에서 가능한 Issue 타입을 제목에 표시

```
[Feat] 이상탐지 모델 추가
[Fix] 데이터 검증 버그 수정
[Docs] README 업데이트
[Test] 모델 평가 테스트 추가
[Research] 금융데이터 분류 연구
[Study] 이상탐지 알고리즘 스터디
```

**선택지:**

| 태그 | 설명 | 용도 |
|---|---|---|
| `[Feat]` | 새 기능 | 이상탐지 모델 추가 |
| `[Fix]` | 버그 수정 | 데이터 검증 버그 수정 |
| `[Docs]` | 문서 | README 업데이트 |
| `[Test]` | 테스트 | 모델 평가 테스트 추가 |
| `[Research]` | 연구 | 금융데이터 분류 연구 |
| `[Study]` | 학습 | 이상탐지 알고리즘 스터디 |
| `[CI/CD]` | 배포/자동화 | - |
| `[Refactor]` | 코드 정리 | - |

## 9. 착수 조건 (Definition of Ready, DoR) (미합의)

**상태:** 팀이 합의한 기록 없음

### 9-1. DoR 제안

Ticket을 Sprint에 포함시키기 전 확인 항목:

- [ ] Ticket 제목이 명확한가 (동사+목표)
- [ ] Ticket 설명이 있는가 (배경, 목표, 인수 조건)
- [ ] 추정 작업량이 명시되었는가 (또는 "추정 불가")
- [ ] 담당자 또는 담당팀이 정해졌는가
- [ ] 의존성(다른 Ticket·외부 작업)이 명시되었는가
- [ ] 마감일이 합리적인가 (Sprint 기간 내인가)

## 10. 완료 조건 (Definition of Done, DoD) (미합의)

**상태:** 팀이 합의한 기록 없음

### 10-1. DoD 제안

Ticket을 "완료"로 표시하기 전 확인 항목.

#### 개발

- [ ] 코드 작성 완료
- [ ] 로컬 테스트 완료
- [ ] PR 제출 (리뷰어 최소 1명 이상)
- [ ] 코드 리뷰 승인됨
- [ ] 메인 브랜치 머지됨

#### 테스트

- [ ] 단위 테스트 작성됨 (또는 불가능한 이유 기록)
- [ ] 통합 테스트 통과
- [ ] 수동 테스트 완료 (QA 항목이 있는 경우)

#### 문서

- [ ] 코드 주석/docstring 작성됨
- [ ] 관련 문서 업데이트됨 (API 명세, 아키텍처 문서 등)
- [ ] 특이사항이 있으면 Ticket에 기록됨

#### 배포

- [ ] CI/CD 파이프라인 통과
- [ ] 필요한 경우 배포되었거나, 배포 준비 완료 상태

### 10-2. Issue별 DoD 차이

**Docs, Study, Research의 경우:**
- [ ] 산출물이 명확한가 (문서 링크, 발표 슬라이드 등)
- [ ] 팀이 검토했는가
- [ ] Notion에 결과물이 링크되었는가

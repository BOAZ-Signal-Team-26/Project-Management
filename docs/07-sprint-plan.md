## 0. 문서의 용도와 읽는 법

이 문서는 `docs/06-wbs.md`의 작업 분해 구조를 스프린트 캘린더(`docs/05-timeline.md` 5절)에 매핑해 스프린트별 생성 티켓 목록을 정리한 자료. WBS는 Epic과 하위 작업의 분해 구조, 이 문서는 그 하위 작업을 스프린트 단위로 배치한 실행 계획. Epic·WBS·티켓의 계층 관계는 노션 컨벤션 DB의 「WBS와 Epic이 무엇이고 서로 어떤 관계인지」 문서 참조.

09-02 확정 전제 **(사실, 팀장 확정 2026-09-02)**

1. 스프린트 주기가 2026-09-03부터 1주에서 2주로 변경. 스프린트 총 8개(Week 3 ~ Week 10)
2. 노션 「Sprint 관리」 DB에는 Week 3까지만 등록. Week 4 이후는 이 문서와 `docs/05-timeline.md` 5절을 기준선으로 삼아 착수 시점에 등록

4. 여유 0일 마감 4건(관문 A, 관문 B, DE 인계 명세 승인, 관문 C, 정규화 완료, 정합화 — 아래 표 참조)을 스프린트 종료일로 정렬. 종료 미팅에서 인수 판정을 그 자리에서 처리 가능

## 10. 노션 등록 절차 (Week 4 이후)

각 스프린트 착수 시점에 아래 절차로 노션 「Sprint 관리」 DB에 등록 (제안)

1. 스프린트 시작일에 「Sprint 관리」 DB에 신규 페이지 생성
2. `Sprint 주기`(제목)에 스프린트 명칭 입력 (예: "Week 4")
3. `기간`(날짜 범위)에 본 문서 해당 절의 시작일~종료일 입력
4. `Sprint 완료 유무` 초기값 "시작 전"으로 설정. 착수 후 "진행중", 종료 후 "완료"로 갱신
5. `진행 상태` 초기값 "Next" 또는 "Future"로 설정. 착수 시 "Current"로 변경, 직전 스프린트는 "Past"로 변경
6. `스프린트 ID`는 자동 증가 필드. 값 지정하지 않음
7. `엔지니어링 작업` 관계 필드에 본 문서 해당 절 "생성할 티켓" 표의 티켓 페이지 연결
8. 티켓 DB의 `Sprint (스프린트)` 관계 필드는 배열 형식. 해당 스프린트 페이지 URL을 배열에 추가하는 방식으로 역방향 연결
9. 직전 스프린트의 `진행 상태` "Past" 갱신 시점·담당 [확인 필요]

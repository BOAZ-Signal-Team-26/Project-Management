## 0-0. 스프린트 문서 틀 **(사실, 09-20 확정)**

Notion 「Sprint 관리」 DB의 스프린트 문서는 **여섯 절만** 씁니다 — **스프린트 목표 / 배경 /
범위 / 범위 외 / 마일스톤 / 완료 조건.** 다른 절을 추가하지 않습니다.

**적는 것은 기획 시점의 계획뿐입니다.** 스프린트가 끝난 뒤 결과를 반영하러 돌아오지
않습니다 — 진행 결과와 달성 여부는 **티켓**이 갖고, 못 한 것은 **다음 스프린트 문서의
「배경」**으로 넘어갑니다.

검토 결과·실측 기록은 **티켓**이나 **엔지니어링 문서**로, 미팅 안건은 **회의록**으로,
설계 상세는 **설계 저장소**로 갑니다. 상세는 [templates/sprint-page.md](../templates/sprint-page.md).

**근거**: 09-20에 Week 3 문서에 정정·검토 결과·진행 상황이 본문으로 섞여 들어가
**원래 계획이 무엇이었는지가 안 보이게** 됐습니다. 계획이 지워지면 「이걸 왜 하기로
했더라」에 답할 문서가 사라집니다.

## 10. 노션 등록 절차 (Week 4 이후)

각 스프린트 착수 시점에 아래 절차로 노션 「Sprint 관리」 DB에 등록 (제안)

1. 스프린트 시작일에 「Sprint 관리」 DB에 신규 페이지 생성
2. `Sprint 주기`(제목)에 스프린트 명칭 입력 (예: "Week 4")
3. `기간`(날짜 범위)에 본 문서 해당 절의 시작일~종료일 입력
4. `Sprint 완료 유무` 초기값 "시작 전"으로 설정. 착수 후 "진행중", 종료 후 "완료"로 갱신
5. `진행 상태` 초기값 "Next" 또는 "Future"로 설정. 착수 시 "Current"로 변경, 직전 스프린트는 "Past"로 변경
6. `스프린트 ID`는 자동 증가 필드. 값 지정하지 않음
7. `엔지니어링 작업` 관계 필드에 본 문서 해당 절 "생성할 티켓" 표의 티켓 페이지 연결
8. 티켓 DB의 `Sprint (스프린트)` 관계 필드는 배열 형식. 해당 스프린트 페이지 URL을 배열에 추가하는 방식으로 역방향 연결
9. 직전 스프린트의 `진행 상태` "Past" 갱신 시점·담당 [확인 필요]

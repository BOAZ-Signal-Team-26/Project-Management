### 1-(b) HWP 파싱은 실제로 어떻게 하나

실측 문구 "olefile + zlib 조합으로 12/12 성공"은 HWP 5.0(OLE Compound File) 포맷을 직접 다룬 것이다. 구조: `olefile`로 `BodyText/SectionN` 스트림을 열고, 각 스트림은 zlib 압축되어 있어 `zlib.decompress`로 해제한 뒤, 레코드 헤더(태그ID+레벨+크기)를 파싱해 UTF-16LE 텍스트를 뽑는다.

**권고: 이 저수준 구현을 유지하지 말고 `pyhwp`(hwp5 파이썬 패키지, `hwp5txt` CLI) 채택을 검토하라.** pyhwp가 내부적으로 동일한 olefile+zlib 스택을 쓰므로 실측 결과가 그대로 재사용 가능하고, 레코드 파싱 버그를 직접 유지보수할 필요가 없다. `hwp5txt input.hwp > output.txt`로 1차 텍스트를 뽑고, 절 경계는 별도 정규식(아래 3절)으로 처리한다.

### 1-(c) LLM 6필드 정확도 검증 50건이 충분한가

**부족하지 않지만 정밀하지도 않다.** n=50, 필드별 이진 채점(정답/오답) 기준 정확도 90%가 나왔다고 가정하면 Wilson 95% 신뢰구간은 약 [0.78, 0.96] — 폭 약 18%p. "필드가 대체로 쓸 만하다"는 정성 판단에는 충분하지만, 필드 간 정확도를 서로 비교하거나 "85% 이상"을 엄밀히 주장하기엔 약하다.

**권고:** 50건을 그대로 유지하되 용도를 좁힌다.
- 6필드 전체 스크리닝(50건)으로 명백한 결함 필드를 먼저 골라낸다.
- 축소 3순위(6필드→3필드, 결정 기한 10-21/10-28)가 발동하면, 살아남은 3필드에 한해 표본을 100건으로 늘려 재검증한다. 필드 수가 절반으로 줄면 검증 공수도 절반으로 줄어 표본을 늘릴 여력이 생긴다.
- 정확도 수치는 반드시 필드별로 분리해서 보고한다("전체 90%"가 아니라 "위험등급 95%, 핵심위험문구 70%" 식). 자유 텍스트 필드(핵심위험문구)는 구조화 필드(위험등급)보다 낮게 나올 것을 미리 알린다.

## 2. 하위 작업의 실제 내용과 합격 기준

### 「수집 모듈 4종 머지」(주영, ~09-30)

4개 커넥터 = API용 1개(통합비교공시) + 정형 HTML용 1개(DART) + PDF용 1개(제재공시, 결정문 PDF본) + HWP용 1개(결정문 HWP본). 공통 인터페이스를 먼저 정의해야 병렬 개발이 가능하다.

```python
def fetch_new_documents(since: date) -> list[RawDocument]: ...

RawDocument = {
    "문서ID": str, "소스": str, "원본경로": str,
    "수집시각": datetime, "raw_content": bytes,
    "상품ID": str | None,
}
```

저장 형태: `raw/{source}/{문서ID}.{ext}` 로 파일 저장 + `raw_documents` 인덱스 테이블(문서ID, 소스, 수집시각, 파일경로, 상태)에 메타데이터 적재.

**합격 기준:** 4개 커넥터 각각 실제 수집 10건 이상 성공 로그. 동일 커넥터 재실행 시 이미 수집한 문서ID 재요청 0건(증분 동작 확인).

### 「원문 정규화」(주영, ~10-14)

함수 `normalize(raw_document) -> list[Section]`, `Section = {문서ID, 절순번, 절제목, 절본문}`.

| 소스 | 절 분할 방법 |
|---|---|
| DART(HTML) | 목차 태그(`h2`/`h3` 등) 기준 분할. 목차 고정 구조이므로 규칙 기반으로 충분 |
| 제재공시(PDF) | `pdfplumber`로 텍스트 추출 → 어절 공백 소실 복원(`PyKoSpacing` 또는 `kiwipiepy`) → 번호 패턴("가.", "1." 등) 정규식으로 절 분할 |
| 결정문(HWP) | `hwp5txt`로 텍스트 추출 → 제재공시와 동일한 절 분할 규칙 적용 |

**합격 기준:** 500건 이상이 `sections` 테이블에 적재. 실패율 리포트(소스별 시도건수/성공건수/실패건수)를 표로 산출.

### 「필드 자동 추출」(주영·민석, ~11-04)

**합격 기준:** 6필드 각각 JSON 스키마 validation 통과율 100%(구조는 항상 나옴), 정확도 표는 50건 기준 필드별 분리 보고, 저신뢰 플래그 비율 산출.

### 「저장 계층·수집 자동화」(주영·대현, ~11-25)

**합격 기준:** 3단 저장(raw/staging/mart) 조인 성공률 리포트(목표 95% 이상), Airflow DAG 무인 실행 2회 연속 성공 로그, 품질 지표 3종(4절) 화면 또는 리포트 존재.

2. HWP는 `pyhwp`(olefile+zlib 기반) 채택을 권장 — 이미 실측 검증된 스택을 재구현할 필요가 없다.
3. 정확도 검증 50건은 스크리닝용으로는 충분하나 정밀 비교엔 부족 — 축소 3순위(6→3필드) 발동 시 살아남은 필드는 표본을 100건으로 늘릴 것.
4. 파싱 실패 정책 3건(격리 큐/부분 성공 허용/폴백·재시도 상한)과 품질 지표 3종(실패율/누락률/일관성)을 4절에 구체 수치로 제시했다.
5. 이번 주 즉시 결정할 5건 중 "공통 인터페이스 확정"과 "라이브러리 확정"이 Week 4 착수를 좌우하는 최우선 항목이다.

# 프로젝트 브리프 (Notion 원문 발췌, 2026-08-19 확정)

## 최종안: 금융상품 설명 리스크 진단 파이프라인

**한 줄 정의** — 판매 중인 금융상품 설명서를 전수 수집·구조화하여 "설명이 어려운 상품"을 정량 진단하고, 실제 분쟁 이력과 대조해 비대면 판매 프로세스 개선안을 도출하는 데이터 파이프라인.

**프레이밍** — 불완전판매는 상담 녹취를 봐야 잡히는데 그건 은행 내부 데이터. 판매 시점에 고객이 받는 문서가 애초에 이해 불가능하면 설명 의무는 형식적으로만 이행됨. 상품 설명서 자체를 데이터로 만들어 난독성을 측정하고 실제 분쟁이 난 상품들과 대조.

### 데이터 소스 (전부 공개 데이터)

### 아키텍처 (원안)
- 수집 층: 소스별 커넥터 분리. API 있으면 API, 없으면 공시 목록 페이지 기반 문서 다운로드. Airflow DAG 주간 스케줄. 신규·개정 문서만 증분 수집.
- 파싱 층: PDF/HWP → 텍스트. 가장 고생하는 구간. 표 구조 붕괴, 스캔본 혼재, 레이아웃 불규칙. 파싱 실패 건은 별도 큐 격리, 실패율을 지표로 관리.
- 구조화 층: LLM으로 필드 추출: 상품유형, 판매사, 위험등급, 수수료 체계, 원금손실 가능성 고지 위치, 핵심 위험 문구. 스키마 고정 + JSON 강제 출력. 추출 신뢰도 낮은 건 플래그.
- 적재 층: raw / staging / mart 3단. 상품 마스터 차원 테이블, 문서는 팩트. 상품 차원에 SCD Type 2로 개정 이력 보존.
- 품질 층: 필수 필드 누락률, 파싱 실패율, LLM 추출 일관성(재추출 일치율) 모니터링.

### 분석 설계
**CDI (Comprehension Difficulty Index, 설명 난독성 지표)** 4축:
- 언어 복잡도: 평균 문장 길이, 피동·이중부정 빈도, 한 문장 내 조건절 중첩 수
- 용어 부담: 금융 전문용어 밀도, 초출 용어 중 설명 없이 사용된 비율
- 구조 접근성: 원금손실·수수료·중도해지 조항의 문서 내 위치(앞쪽일수록 유리), 전체 분량
- 고지 충실도: 금소법상 설명 의무 항목 포함 여부 체크리스트
각 축 정규화 → 상품별 종합 점수 → 상품군별·판매사별 비교.
**후속 확정(프로젝트 구체화 Epic):** 절대점수가 아니라 위험등급·상품유형 통제 후 **잔차**를 최종 지표로 사용. 고지 충실도 축은 변별력이 낮을 가능성이 높아 점수 축이 아닌 누락 검출 필터로 재정의.

**검증(H1)** — 분쟁조정 결정문에 등장한 상품군의 CDI가 그렇지 않은 상품군보다 유의하게 높은지 확인. 차이가 안 나와도 유효한 발견("문서 외 요인이 크다")으로 미리 규정.
**한계** — 분쟁 사례 수백 건은 검정력 제한. "탐색적 분석"으로 규정.

### 산출물
1. 상품별 설명 리스크 대시보드 (메인): 상품군·판매사별 CDI 분포, 개별 상품 드릴다운, 감점 항목 분해
2. 분쟁 사례 탐색 뷰: 위반 유형별·상품군별 분쟁 이력, 유사 사례 검색(임베딩)
3. 비대면 가입 프로세스 개선안: 실제 앱에서 펀드·ELS 가입 플로우를 밟고 CDI 결과와 연결한 개선안
4. 파이프라인 문서: 아키텍처 다이어그램, 스키마 정의, 데이터 품질 리포트

**축소 순서** — 유사 사례 검색(임베딩) → SCD 이력 관리 → 상품군 축소(펀드·ETF만). **절대 자르면 안 되는 것**: CDI 산출, 대시보드, 개선안.

### 예상 질문
- "문서만 봐서 불완전판매를 알 수 있나" → 문서는 설명 의무의 필요조건, 판매 전 통제 가능한 유일한 지점
- "CDI 가중치는 어떻게" → 가장 약한 고리. 임의 설정 인정 + 민감도 분석 실제 수행
- "LLM 추출 신뢰 가능?" → 수동 검증 표본·정확도 수치 필수

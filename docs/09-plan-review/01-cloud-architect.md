# 클라우드·데이터 아키텍처 관점 검토

**작성:** 외부 자문 (클라우드/데이터 아키텍트), 2026-09-08. 대상: 05-timeline / 06-wbs / 07-sprint-plan / 08-m1-decisions
**전제:** 학생 4인, 학기 중 파트타임, 학습 우선, 예산 상한 월 1~2만원. 환율 1,450원/USD 가정

계획 문서의 구조(3관문 분할, 여유 0일 정렬, 결정 기한 역산, 축소 순서)는 학생 팀 기준으로 이미 충분히 촘촘합니다. 부족한 것은 계획의 밀도가 아니라 **산출물의 정의와 합격 기준**입니다.

**3단 저장 계층 raw/staging/mart는 유지해야 합니다.** 다만 "3개 시스템"이 아니라 **1개 Postgres 인스턴스의 스키마 3개**로 관문 A에서 못박아야 합니다. 초심자 팀이 이 말을 "저장소 3개 구축"으로 읽으면 공수가 3배가 됩니다. 계층 자체는 파싱 실패 격리와 재산출(M5 전수 대조)의 전제이므로 컷 대상이 아닙니다.

## 2. 관문 A/B/C 산출물 명세와 합격 기준

### 2-1. 관문 A (09.16) — 논리 스키마·raw 적재 규약·실패 처리 정책

**산출물 1: 논리 스키마 (실행 가능한 DDL)** — 08 문서 3절 표를 컬럼 수준으로 확정한 형태. 최소 6테이블

| 테이블 | 행 정의 | 최소 컬럼 |
|---|---|---|
| `dim_product` | 상품 1건 | `product_id`(PK), `product_name`, `product_type`, `seller_name`, `seller_code`, `risk_grade_raw`, `risk_grade_norm`, `source_code`, `first_seen_date` |
| `fact_document` | 설명서 1건 = 1행 | `doc_id`(PK), `product_id`(FK), `source_code`, `disclosure_date`, `doc_url`, `raw_object_key`, `char_len`, `section_count`, `parse_status`, `is_amendment`, `prev_doc_id` |
| `doc_section` | 문서의 절 1개 | `doc_id`(FK), `section_seq`, `section_title`, `section_level`, `char_start`, `char_end` / PK(`doc_id`,`section_seq`) |

| `parse_failure_queue` | 실패 건 1개 | `doc_id`, `failure_type`, `failure_detail`, `occurred_at`, `retry_count` |

조인 키 4종: `product_id`(문서↔상품), `(product_type, seller_name)`(상품↔분쟁 라벨, 간접 연결), `doc_id`(문서↔절·실패큐), `clause_id`(체크 결과↔조문).

**합격 기준 (4항 전부 충족)**
- [ ] 6테이블 `CREATE TABLE`이 **실제 DB에서 실행되어 생성됨**. 문서만 있는 상태는 미통과
- [ ] 샘플 20건을 넣고 조인 키 4종으로 `SELECT` 실행 → 고아 행 0건
- [ ] `risk_grade_raw`(1~6 역방향) → `risk_grade_norm` 변환식이 매핑 표로 명시됨
- [ ] `fact_document` 1행 = 문서 1건이 CDI 산출 단위 결정(문서 전수)과 일치함

**산출물 2: raw 적재 규약** — 경로 `raw/{source_code}/{yyyymm}/{doc_id}.html`. 메타 필드 5종(수집 시각, 원 URL, HTTP 상태, 바이트 수, 본문 SHA-256). 중복 판정 키는 원 URL + 해시이며 재수집 시 덮어쓰기를 금지하고 해시가 다르면 `doc_id`에 접미사를 부여
- **합격:** 샘플 20건이 규약대로 저장되고, 같은 스크립트를 두 번 실행해 신규 적재 0건

**산출물 3: 실패 처리 정책 3건** — 각 정책이 `탐지 조건 / 재시도 / 최종 처분 / 지표 이름` 4열을 채워야 함

| 정책 | 탐지 조건 | 재시도 | 최종 처분 | 지표 |
|---|---|---|---|---|
| 수집 실패 | HTTP 4xx·5xx·타임아웃 | 3회, 지수 백오프 | `parse_failure_queue` 적재 | 수집 실패율 |
| 파싱 실패 | 절 경계 미검출 / 본문 0자 | 없음 | 격리 큐 이동, CDI 산출 제외 | 파싱 실패율 (M2 조건) |
| 추출 실패 | JSON 스키마 위반 / `confidence` < 0.6 | 1회 재호출 | `parse_status='extract_failed'` | 저신뢰 플래그율 |

**합격:** 4열 공란 0건. 임계값(3회, 0.6)이 숫자로 적혀 있어야 통과

**산출물 4 (신설 권고): 코퍼스 규모 결정 기록** — 처리 대상 건수 N, 층화 기준(상품군×판매사), 산출 근거(비용 상한 ÷ 실측 단가)

## 3. 환경별 추천안 (선택지 나열 아님. 추천 1개 + 폴백 1개)

### 3-1. 저장 계층 — **Supabase 무료 Postgres 1개 인스턴스, 스키마 3개(`raw`/`staging`/`mart`)**

DB 무료 한도 500MB 안에 들어갑니다. 문서 메타 6,473행·절 약 13만행·CDI 6,473행을 합쳐 100MB 수준입니다. 4인이 같은 접속 문자열로 붙고 대시보드도 같은 DB를 읽으므로, 저장 계층 결정 하나가 대시보드 연결까지 해결합니다.
원문 HTML(약 6.5GB)은 **Cloudflare R2 무료 티어(10GB, 전송 0원)**에 두고 DB에는 `raw_object_key`만 저장합니다. 주의: Supabase 무료 프로젝트는 무활동이 이어지면 일시정지되므로 학기 중 공백 구간에는 수동 재개가 필요합니다.
**폴백:** 로컬 Postgres(Docker) + 주 1회 `pg_dump`를 팀 공용 드라이브에.

### 3-2. 실행 환경 — **주영 로컬 Docker Compose Airflow (LocalExecutor)**

상시 VM 비용이 0원이고 D4의 학습 목적은 로컬에서 완전히 달성됩니다. DAG 소스는 저장소에서 관리하므로 4인이 코드를 볼 수 있습니다.
「무인 실행 2회 연속 성공」 증빙은 스케줄 주기를 일 단위로 임시 변경해 이틀 연속 무개입 실행 로그를 캡처하십시오. 2주간 노트북을 켜 두는 것은 비현실적입니다.
**폴백:** GitHub Actions cron(public 저장소 무료)이 같은 Python 엔트리포인트를 호출. D4의 "상시 교체 허용(Airflow 실패 시 폴백 경로)" 조항과 그대로 맞습니다.

### 3-3. 대시보드 — **Streamlit Community Cloud**

Python만으로 3화면과 드릴다운이 만들어지고 GitHub 연동으로 열람 URL이 자동 발급되며 비용은 0원입니다. 다빈·주영 모두 Python을 쓰므로 06-wbs 7-4절의 "학습 비용 최저 선택지" 조건을 만족합니다(학습 반나절 수준).
단, **public 저장소가 전제이고 앱 URL이 공개됩니다.** 05-timeline 미결 4번(열람 대상 범위)을 D6 기한(11.11)이 아니라 지금 결정해야 시크릿 정책이 확정됩니다. 비공개가 필요하면 앱 최상단 비밀번호 게이트 1개로 충분합니다.
**폴백:** Hugging Face Spaces(Streamlit 런타임, private 가능, 무료).

| 방식 | 입력 토큰 | 비용 (Haiku 4.5, 1,450원/USD) |
|---|---|---|
| 전문 투입, 전수 6,473건 | 약 1,294M | 약 190만원 |
| **발췌 투입(문서당 4,000토큰), 전수 6,473건** | 약 26M | **약 11만원** |
| 위 + Batch API 50% | 약 26M | **약 5.5만원** |
| 발췌 + 표본 1,500건 + Batch | 약 6M | 약 1.3만원 |

발췌가 가능한 근거는 실측입니다. DART HTML은 목차 구조가 고정되어 있으므로 원금손실·수수료·중도해지·위험등급 4개 구간을 규칙으로 잘라낼 수 있고, LLM은 그 발췌만 읽습니다.
**비용 상한 10만원을 권합니다.** 전수 처리에 재실행 여유까지 들어가며, **축소 3순위(추출 필드 6→3)는 발동할 필요가 없어집니다.**
**폴백:** 상한 초과 시 층화 표본 1,500건으로 자동 축소(모델 교체가 아니라 규모 축소가 폴백).

### 3-5. 시크릿과 백업 — **공유 시크릿을 1개로 줄인다**

공개 API 인증키 4종은 1인 1키 발급이 가능하므로 **공유 자체를 없앱니다.** 각자 자기 키를 발급해 자기 `.env`에 두고, 저장소에는 `.env.example`만 커밋합니다. 공유가 필요한 것은 유료 LLM API 키 1개뿐이며, 결제 주체(대현)가 보관하고 Airflow 호스트와 GitHub Actions Secrets에 대현이 직접 주입합니다. **폴백:** Bitwarden 무료 계정의 Send 기능으로 1회성 전달.
백업 대상도 같은 방식으로 줄입니다. raw(재수집 가능)·staging·mart·CDI 점수는 모두 재생성 가능하므로 백업 대상이 아닙니다. **재생성 불가 자산은 4종뿐입니다:** 수동 라벨 테이블, 검증 50건 채점 결과, 단가 실측표, 결정 기록. 이 4종을 `data/manual/`에 두고 git에 커밋하면(수백 KB) 복구 절차가 `git clone` 한 줄로 끝납니다. 프로비저닝 산출물 「백업 주기·복구 절차 문서」를 이 규칙으로 대체하면 해당 작업이 하루에서 1시간으로 줄어듭니다.

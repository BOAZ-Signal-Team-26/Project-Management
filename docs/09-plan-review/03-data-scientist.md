## 1. CDI 4축 설계와 잔차 설계의 타당성

### 1-1. 결론
잔차 설계(위험등급·상품유형 통제 후 잔차를 최종 지표로) 자체는 타당하다. 위험등급이 높은 상품일수록 설명서가 본질적으로 길고 전문용어가 많아지므로, 원점수만 비교하면 "어려운 상품군"과 "설명이 나쁜 상품"이 뒤섞인다. 잔차는 이 둘을 분리한다. 다만 **위험등급과 상품유형이 서로 강하게 얽혀 있을 위험**이 있다(예: 파생결합증권은 대부분 고위험 등급에 몰림). 회귀 전에 반드시 VIF(분산팽창지수)를 확인하고, 10을 넘으면 상품유형 더미 중 희소 범주를 통합해야 한다.

또한 08-m1-decisions.md의 결정대로 **고지 충실도 축은 가중합에서 제외하고 누락 검출 필터로 재정의**한 것에 동의한다. 이 축은 이분법적 체크리스트라 연속 점수와 척도가 다르고, 가중치를 어떻게 줘도 해석이 어색해진다.

### 1-2. 축별 계산식 (구체화)

| 축 | 변수 | 계산식 | 비고 |
|---|---|---|---|
| 언어복잡도 | 평균 문장 길이 | `mean_sent_len = total_어절수 / num_문장수` | 형태소분석기의 어절 분리 결과 사용 |
| | 피동 표현 빈도 | `passive_ratio = count(피동 형태소 태그: '-되다','-어지다','-당하다', 접미사 '이/히/리/기') / num_문장수` | 형태소분석기 POS 태그로 패턴 매칭 |
| | 이중부정 빈도 | `double_neg_ratio = count(한 문장 내 부정소 2개 이상: '안','못','-지 않다','-지 못하다') / num_문장수` | |
| | 조건절 중첩 수 | `cond_depth = mean(문장별 연결어미 '-면','-을 경우','-거나' 등장 횟수)` | 문장당 평균 |
| 용어부담 | 전문용어 밀도 | `term_density = count(용어사전 매칭 토큰) / total_토큰수` | 용어사전 출처는 1-3절 |
| | 미설명 초출 비율 | `undefined_term_ratio = count(전문용어 종류 중 최초 등장 문장·인접 1문장 내 정의구('~란','~을 말한다', 괄호설명) 부재) / count(전문용어 종류수)` | 종류(type) 기준, 등장횟수(token) 아님 |
| 구조접근성 | 조항 위치 점수 | `position_score = 1 - (원금손실/수수료/중도해지 조항이 등장한 절 순번 / 전체 절 수)` | 절 단위 메타데이터 필요 → 2절 참조 |
| | 전체 분량 | `length_z = (총 어절수 - 상품유형별 평균) / 상품유형별 표준편차` | 상품유형 내 z-score. 전체 모집단 대비가 아님 |
| (필터) 고지 충실도 | 누락 항목 수 | `missing_count = count(금소법 19조 하위 체크리스트 항목 중 문서 내 대응 문구 없음)` | 점수화 대상 아님. `missing_count > 0`이면 별도 플래그 컬럼 |

CDI 원점수 = `w1*언어복잡도_정규화 + w2*용어부담_정규화 + w3*구조접근성_정규화` (3축, 정규화는 상품유형 내 min-max 또는 percentile-rank). 최종 CDI는 `CDI_원점수 ~ 위험등급 + 상품유형` OLS의 잔차.

## 2. CDI 산출 단위

08-m1-decisions.md의 권고(안 1: 문서 전수, 절 정보는 구조접근성 축 입력으로 보관)에 **동의**한다. 추가로 짚을 지점은 DE 정규화 단위와의 접합부다.

- **DE가 넘겨야 할 정규화 출력 단위는 절(section) 단위**여야 한다. `문서ID, 절순번, 절유형(원금손실/수수료/중도해지/기타), 절텍스트`가 최소 스키마다. CDI 산출은 이 절 단위 테이블을 문서ID로 GROUP BY해서 문서 전수로 접는다.
- 즉 **DE 인계 명세서(09-30 마감)에 "절 경계 보존"이 산출물로 명시되어야 한다.** 현재 06-wbs.md에는 "인계 명세서"라고만 되어 있고 절 단위 보존 요구가 문면에 없다. 다빈이 DE 인계 명세 작성 시 이 요구를 필드로 못박지 않으면, 주영이 문서 전체를 하나의 블롭으로 정규화해버릴 위험이 있고, 그러면 구조접근성 축 자체가 계산 불가능해진다.

## 3. 검증 트랙 H1

### 3-1. 08-m1-decisions.md가 놓친 문제: 의사 반복(pseudo-replication)

08 문서의 "상품군 4종 가정 시 군당 약 47건, 중간 효과크기 탐지 가능"이라는 검정력 계산은 **문서(6,473건)를 독립 관측치처럼 취급**하고 있다. 그러나 실제로는 같은 상품군×판매사 조합에 속한 문서들이 모두 같은 라벨(분쟁군/비분쟁군)을 공유하므로, **독립 관측치의 실질 개수는 문서 수가 아니라 상품군×판매사 조합의 개수(십 단위)**다. 이 둘을 혼동하면 표준오차가 과소추정되어 거짓 양성(false positive)이 나온다.

### 3-2. 현실적 검정 설계

| 항목 | 권고 |
|---|---|
| 분석 단위 | **1차: 상품군×판매사 조합**(약 10~40개 추정). 조합별로 소속 문서의 CDI 잔차 평균을 집계한 값이 관측치 |
| 검정 방법 | 조합 수가 적으므로(정규성 가정 불안정) **Mann-Whitney U 검정** 또는 **순열검정(permutation test, 라벨을 1,000회 무작위 재배정)**을 1차 방법으로 채택. 정규성이 확보되면 Welch's t-test를 보조로 병기 |
| 2차(탐색적) | 문서 단위 회귀 `CDI잔차 ~ 분쟁여부` + **판매사 클러스터 강건표준오차(cluster-robust SE)**. 위험등급·상품유형은 잔차 계산에서 이미 통제됐으므로 이 모델에서 재투입하지 않는다(이중통제 방지) |
| 최소 표본 | 조합 수 기준 그룹당 최소 8~10개는 확보해야 순열검정이 의미 있다. 187건 분쟁결정문이 몇 개의 고유 상품군×판매사 조합으로 접히는지(A-2 확인 항목)를 먼저 세어야 하며, 두 자릿수 미만이면 검정 자체를 "탐색적 사례 비교"로 격하해야 한다 |
| 효과크기 기대치 | d=0.2~0.3(작음) 수준을 현실적 기대치로 잡는다. 라벨이 상품군×판매사 단위로 뭉뚱그려져 있어 신호가 희석되기 때문 |

### 3-3. 사전 등록 문서화

"차이가 안 나와도 유효한 발견"이라는 프레이밍을 지키려면, **분석 코드를 짜기 전에** 아래를 문서(예: `docs/h1-preregistration.md`)로 고정한다.

1. 가설: H1(분쟁군 CDI잔차 > 비분쟁군), H0(차이 없음)
2. 1차 분석 방법: 조합 단위 순열검정, 유의수준 α=0.10(표본이 작으므로 0.05보다 완화하되 사전에 명시)
3. "유의하지 않음"의 해석을 미리 못박는다: "문서 외 요인(구두 설명, 소비자 사전지식, 시장 상황)이 지배적"이라는 결론으로 채택하고, 이를 비대면 가입 프로세스 개선안 Epic의 근거로 전환한다고 명시
4. 다중비교: 상품군별로 쪼개서 여러 번 검정하지 않는다. 쪼갤 경우 Bonferroni 보정 적용을 사전에 명시

## 4. 민감도 분석 2종 — 구체 설계

| 구분 | 설계 |
|---|---|
| **① 가중치 섭동** | 기준 가중치(균등 1/3씩, 정당화는 7절 참조)에서 Dirichlet(α=1,1,1) 분포로 N=1,000회 가중치 조합을 샘플링. 매회 CDI 재계산 후 전체 상품 순위와 기준 순위 간 **Spearman ρ** 산출. 1,000개 ρ값의 중앙값과 5~95% 구간을 리포트 |
| **② 정규화 방식 민감도** | 각 축 정규화를 min-max ↔ percentile-rank로 교체했을 때 순위가 얼마나 흔들리는지 확인. 두 정규화 방식 각각으로 CDI 산출 후 Spearman ρ와 **상위 10%(약 647건) top-k 겹침 비율(Jaccard index)** 비교 |
| 공통 지표 | Spearman ρ, top-k Jaccard(k=상위 10% 및 대시보드 노출 상위 20개 상품 별도 산출) |
| 판정 기준(제안) | ρ < 0.7 또는 top-k Jaccard < 0.5이면 "가중치·정규화 선택에 결과가 취약함"으로 보고서에 명시하고, 결론 문장에 "순위는 가중치 선택에 민감하다"는 단서를 단다 |

# 스프린트 문서 틀 (Notion 「Sprint 관리」 DB)

**이 여섯 절만 씁니다. 다른 절을 추가하지 않습니다.**

```
## 스프린트 목표
## 배경
## 범위
## 범위 외
## 마일스톤
## 완료 조건
```

## 왜 고정하는가

**스프린트 문서는 기획 시점의 계획서입니다.** 스프린트를 시작할 때 「무엇을 왜 하기로 했는지」를
적는 곳이지, 그 뒤에 무엇이 어떻게 됐는지를 적는 곳이 아닙니다.

진행 중에 나온 검토 결과·정정·안건을 그때그때 덧붙이면, 나중에 읽는 사람이 **무엇이 이
스프린트의 계획이고 무엇이 도중에 붙은 메모인지** 구분하지 못합니다. 계획이 지워지면
**「우리가 이걸 왜 하기로 했더라」에 답할 문서가 사라집니다.**

09-20에 Week 3 문서에서 실제로 이 일이 있었습니다. 기간 필드 정정, 실측으로 뒤집힌 항목,
분담 문제의 원인, 진행 결과 같은 것이 본문에 섞여 들어가 **원래 계획이 무엇이었는지가 안
보이게** 됐습니다.

## 각 절에 무엇을 쓰나

| 절 | 내용 | 쓰지 않는 것 |
|---|---|---|
| **스프린트 목표** | 이 스프린트가 끝났을 때 무엇이 되어 있어야 하는지. **한두 문장** | 작업 목록 |
| **배경** | 왜 이 목표인가. 앞 스프린트에서 넘어온 것, 지금 막혀 있는 것 | 결과 보고 |
| **범위** | 이번에 하는 것. 사람 / 티켓 / 마감 / 산출물 표 | 상세 설계 |
| **범위 외** | 이번에 **하지 않는** 것과 그 이유. 다음 스프린트로 넘기는 것 | — |
| **마일스톤** | 날짜와 그날 무엇이 있어야 하는지 | — |
| **완료 조건** | 기획 시점에 합의한 **「무엇이 있으면 끝인가」**. 체크박스 | 진행률, 달성 여부, 사유 |

## 넣지 않는 것

아래는 **전부 다른 곳에 자리가 있습니다.** 스프린트 문서에 쓰지 않습니다.

| 내용 | 어디로 |
|---|---|
| 검토 결과·실측 기록 | 해당 **티켓** 또는 **엔지니어링 문서** |
| 설계 상세, 표 구조, API 명세 | **엔지니어링 문서** |
| 미팅 안건과 결론 | **회의록** |
| 관문 이관 목록, 미확인 항목 | 설계 저장소 (`gate-a/`) |
| 문서 정정 이력 | 고친 문서 자체에 남깁니다 |

## 스프린트가 끝난 뒤에는 고치지 않습니다

**기획 시점의 계획 그대로 둡니다.** 결과를 반영하러 돌아오지 않습니다.

| 하고 싶어지는 것 | 실제로 해야 하는 것 |
|---|---|
| 「한 일」 절을 덧붙인다 | 각 **티켓**에 적습니다. 티켓이 결과의 자리입니다 |
| 완료 조건에 체크하고 사유를 단다 | **티켓의 완료 조건**에 체크합니다 |
| 못 한 것을 적어 둔다 | **다음 스프린트 문서의 「배경」**에 「앞 스프린트에서 넘어온 것」으로 씁니다 |
| 계획이 틀렸다고 적는다 | 다음 스프린트 문서의 「배경」에 씁니다 |

예외는 **기획 시점에 잘못 적은 사실을 바로잡는 것**뿐입니다(날짜 오기 등). 이때도 절을
새로 만들지 않고 틀린 값만 고칩니다.

**결과가 어디 있는지 알고 싶으면** 스프린트 문서가 아니라 그 스프린트에 달린 티켓 목록을
봅니다. Notion Sprint 문서 상단의 티켓 뷰가 그 역할을 합니다.
